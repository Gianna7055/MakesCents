RolloverEnvelopeEntityModel

Model for a rollover envelope's persistent definition. No dollar amounts live here - a rollover envelope isn't guaranteed to be active every month, so amounts live on the per-month instance (see RolloverEnvelopeMonthEntityModel).

RolloverEnvelopeMonthEntityModel

Model for a single month's instance of a rollover envelope. Absence of a row for a given (RolloverEnvelopeId, BudgetMonthId) pair means the envelope was inactive that month.

SetBudgetTemplateEnvelopeItemRequest

Request model for a single item within a template's envelope list being set. BudgetTemplateEnvelopeId is null for a brand new entry, or the existing entry's id to update it in place.

SetBudgetTemplateEnvelopesRequest

Request model to set (create/reorder/update/remove all at once) a template's envelope entries. The list's order is the funding priority for whenever this template is applied.

SetEnvelopeFundingItemRequest

Request model for a single item within a funding queue being set. EnvelopeFundingId is null for a brand new row, or the existing row's id to update it in place.

SetEnvelopeFundingQueueRequest

Request model to set (create/reorder/update/remove all at once) the funding queue for a budget month. The list's order is the funding priority - item 0 is funded first.

SinkingFundEnvelopeEntityModel

Model for a sinking fund envelope. Sinking fund envelopes are persistent - one row holds a live remaining_amount that carries forward month to month, unlike rollover envelopes.

SummaryEnvelopeResponse

Response model for a single envelope for the Get Budget method. Sinking fund and rollover envelopes come from two different tables with two different id spaces, so IsSinkingFund tells the frontend which table EnvelopeId belongs to (same pattern SummaryAccountDTOModel uses to distinguish bank/debt/investment accounts). RemainingAmount is nullable because a rollover envelope may not be activated for the month being viewed.

TransactionSplitEntityModel

Model for a transaction split model. EnvelopeId is a display/API-level id - IsSinkingFund says whether it refers to a sinking_fund_envelope_id or the persistent rollover_envelope_id (not the month-specific rollover_envelope_month_id, which is an internal DAO detail).

TransactionSplitSnapshotModel

Internal helper: the raw current state of one transaction_split row, used to reverse its old effect on an envelope's remaining amount before an update applies the new one.

TransactionSplitTransferSideModel

Internal helper for reading one side of an envelope-to-envelope transfer back out of transaction_split (used by TransferTransactionDAO/TransactionDAO, not exposed to the API).

TransferTransactionEntityModel

Model for a transfer transaction. v3's transfer_transaction table only carries account columns - an envelope-to-envelope transfer is a transfer_transaction row of type Envelope with null account columns, paired with two opposite-signed transaction_split rows that carry the actual envelope references.

TransferTransactionSnapshotModel

Internal helper: the current type/accounts/total_amount/budget_month_id for a transfer transaction, read before an update is applied so the old effect (account balances or envelope remaining amounts, depending on type) can be reversed and the new one applied.
